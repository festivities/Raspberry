Target: LINE PLAY 10.1.0.0, versionCode 254, APK SHA-256 `aa6495a0430beef0c9a719a1f09fe836ff1c82a0f4f96235d47fffda070b45d1`. Other inputs must be refused. Offsets below are **uncompressed ELF file offsets**, not offsets inside the APK.

## Package and signing changes

The combined build replaces `classes3.dex` and both `libgame.so` entries, and adds `classes5.dex`, both `libraspberry.so` entries and `assets/raspberry/endpoint.json`. An explicit development pin adds one further asset; ordinary builds do not include it. Package name, version, manifest, resources and the other three DEX entries are unchanged.

Re-signing removes obsolete upstream JAR/APK signatures and replaces them with the operator's signatures. `apksigner` also removes the original `stamp-cert-sha256` source-stamp digest; it cannot attest to this new package. ZIP headers/timestamps and alignment are normalized, while retained compressed payloads are copied unchanged. [V] Two private combined signed builds were byte-identical, and their entry/payload comparison matched this inventory. That is packaging evidence, not game acceptance.

## Endpoint routing

Own code: `libraspberry.so`, loaded after `libgame` and before the Cocos renderer initializes. Patch only libgame's GOT slots for `getaddrinfo`, `gethostbyname`, `connect` and `sendto`; do not hook protection, browser or LINE-encryption libraries.

For an allowlisted game hostname, resolve the configured endpoint and return an internal marker address. Only that marker is translated to the endpoint and mapped port at the socket boundary. Matching the endpoint IP itself is unsafe: unrelated destinations may share it. Keep the original URI hostname for Host/SNI. Fail closed when endpoint resolution or hook installation fails.

**Evidence:** both ABIs import those four libc functions. Native curl uses libc resolution; HttpSender passes its resolver sockaddr to `connect`. The LPN path stringifies the resolved IPv4 address and parses that same address before connecting; it does not perform a second DNS lookup. Session host and port can come from `sessionServerInfo`; the gateway port is a client constant. Neither port instruction needs a patch.

**Verify:** an isolated stub on remapped ports must observe original Host/SNI, HTTP, HTTPS and both game sockets. Confirm unrelated resolutions and connections are unchanged, including a connection sharing the endpoint IP. Confirm no allowlisted game hostname reaches device DNS. Actual UDP reply/source-address assumptions remain unproven.

## iOS keyboard geometry guard (2026-11-22)

- **Target:** stock `-[EAGLView onUIKeyboardNotification:]` (`0x10156DF20`, `v24@0:8@16`) and `-[PfEditText_iOS TracePosition_x:y:width:height:]` (`0x1018493F0`, `v32@0:8f16f20f24f28`). Both are runtime method replacements in Raspberry's own dylib. No executable bytes change.
- **Evidence [S + crash reports]:** two physical crashes have the same uncaught `CALayer` geometry exception from `TracePosition` → `setFrame:`: iOS 27.0 chat keyboard (`UITextView`) and iOS 27.2 avatar-name SELECT (`UITextField`). The stock handler scales all keyboard rects by `frameWidth / (beginFrame.width × contentScale / scaleX)`. A zero, negative or non-finite begin width yields inf/NaN. The editor stores these rects (`0x101908AF0`), and `KEYBOARD_SHOW` layers use them to place panels. The device's actual begin rect is not yet captured.
- **Change:** when the begin width is unusable, pass a copied notification to the stock handler with that width taken from the end rect, or else from the view width. Non-finite components are replaced, and every other `userInfo` key and the notification name/object are kept. A notification with no usable width anywhere is withheld. As a backstop, `TracePosition` with non-finite inputs is skipped, so the native editor keeps its previous frame. Pure decisions are in `ios/RBKeyboardGeometry.h`.
- **Guards:** each method must be in the main image with the exact encoding and IMP at the locked RVA, and the replaced IMP must be the stock one. A failed guard is logged and leaves stock behavior unchanged (non-fatal).
- **Logging:** numeric rects only (`raspberry-ios keyboard-geometry …`): the first four unchanged notifications and up to 32 sanitized, withheld or skipped events. No text, objects or identifiers are logged.
- **Device result:** user-verified on the iPhone 15 Pro Max (iOS 27.0, Sideloadly): chat input, Chat ToS Agree and avatar creation no longer abort. The iPhone 16e (iOS 27.2) retest was closed by user decision without verification.
- **Verify:** `ios/RBKeyboardGeometry_test.c` (core gate), strict SDK build. On a device, open chat or the avatar name field and confirm no abort; the unified log shows `guards keyboard=1 trace=1` and the real begin/end rects.
- **Risk:** if iOS reports a begin width that is wrong but positive, it is still used as is. Skipping a non-finite `TracePosition` can leave the native field at its previous position for that frame.
